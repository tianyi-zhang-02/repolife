Keep code understandable.

Tessri reads a codebase and its git history, offline and with nothing else installed, and answers the questions a maintainer asks of a system that grows faster than anyone can read it.

Get started Read the guide
$ pip install tessri

Python 3.11 or newer, no dependencies. To run it once without installing: uvx tessri scan .

What it answers

Four questions, answered from one picture of the code and its history.

How does the system fit together?

The modules, the cycles, and the few dependencies that would break them if cut.

tessri graph

What can this change reach?

The files that depend on it, the tests that reach it, and who is able to review it.

tessri impact <path>

What does nothing reach, and what does nobody maintain?

Every file's status from entry points, tests and configs; owners from history, and who went quiet.

tessri scan .

What did this change do to the structure?

New orphans, new cycles, imports of deleted files, changed code nobody active maintains. Markdown, JSON or SARIF, with an exit code for CI.

tessri check --since main

How does it work?

One pass over the files and the history, then one view per question.

01

Read

Lists the files, parses Python with Python's own parser and JavaScript and TypeScript with its own scanner, and reads configs, scripts and docs for the files they name.

02

Join

Builds the import graph with the kind of evidence behind every edge, and reads from git who changed what, following files through renames.

03

Answer

Each command is one view of that picture: reachability, ownership, module graph, impact, triage and the check of a change.

No model, no network, no service, and it never edits your code. The order triage puts files in was backtested on real history; the composite risk score we tried did not beat its parts, so there is none.

Evidence, not adjectives

Every claim can be traced, and what the analysis cannot see it says it cannot see.

Getting started

Three steps.

  1. Scan a repository. tessri scan . prints the report; --format html --out report.html writes one offline page with the explorer.
  2. Ask before, during and after a change. tessri impact <path> before, tessri triage to review one, tessri check when it is done, tessri brief to hand it over on one page; without --since, a branch is judged against the default branch.
  3. Give it to your agent. tessri integration install --agent claude (or codex) installs the skill with a receipt; tessri integration remove takes it out again.
